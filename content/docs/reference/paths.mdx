所有数据都在用户目录下，没有系统级配置文件（TUN helper 的 LaunchDaemon 除外，那是 macOS 管的）。

    <Folder name="Subscriptions">

## 权限

| 对象 | 权限 |
| --- | --- |
| 目录 | `0700` |
| 文件 | `0600` |

写入方式是「先写唯一临时文件 → 原子 rename」，中途失败会清理临时文件，不会留下半成品，也不会破坏上一份能用的配置。

## Keychain

| 内容 | 索引方式 |
| --- | --- |
| 订阅 URL | 按配置 ID |
| 代理端点密码 | 按端点 ID |

这些不写进 `profiles.json`。

## 运行时产物的代际保留

每次启动生成的运行时配置写在一个带 UUID 的新文件里，而不是覆盖旧的。ClashMax 保留最近若干代，更旧的自动清理。

这样做的直接好处：生成失败时上一份仍然完好；出问题时也能对比前后两代的差异。

## 从 App 里打开

- **状态 → 更多 → 打开日志 / 打开日志文件夹**
- 路由页的 **生效配置** 工具直接显示当前运行时配置的内容（敏感字段已遮蔽）

<Callout type="warn">
直接编辑 `Runtime/` 下的文件没有意义——下次启动会重新生成，你的改动会被覆盖。要改运行时行为，用[路由页的片段库](/docs/advanced/snippets)。
</Callout>

## 彻底清理

删除 `~/Library/Application Support/ClashMax/` 会清掉配置、运行时产物和日志；订阅 URL 和端点密码要在「钥匙串访问」里搜 ClashMax 手动删除；TUN helper 在 **系统设置 → 通用 → 登录项与扩展** 里移除。
