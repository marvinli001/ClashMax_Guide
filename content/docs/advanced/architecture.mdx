## 运行时所有者

同一时刻核心只可能属于五种状态之一。这个概念在 App 里反复出现，很多行为取决于它，尤其是[变更生效模型](/docs/advanced/apply-model)：

| 所有者 | 含义 |
| --- | --- |
| `stopped` | 没有核心在跑 |
| `user` | 用户态核心，系统代理模式 |
| `tunnel` | 特权 helper 启动的核心，TUN 模式 |
| `networkExtension` | Network Extension 持有的核心，NE 代理模式 |
| `preview` | 为延迟测试临时起的预览核心，不承载用户流量 |

`preview` 单独成一档是有原因的：预览核心在跑不等于运行时在服务用户流量，所以此时所有配置修改都归入「下次启动生效」。

## 控制通道

App 不解析核心的 stdout，也不改核心的运行内存。所有交互都走 Mihomo 的 REST + WebSocket 控制面：

| 用途 | 接口 |
| --- | --- |
| 版本、配置 | `GET /version`、`GET /configs` |
| 修改运行模式 / IPv6 / TUN | `PATCH /configs` |
| 重载配置 | `PUT /configs?force=true` |
| 代理组与节点 | `GET /proxies`、`PUT /proxies/{name}` |
| 延迟测试 | 单节点与整组两种 |
| Provider | 更新、健康检查 |
| 规则 | `GET /rules`、rule-provider 更新 |
| 连接 | 列表、关闭单条、关闭全部 |
| DNS | 查询、清空 fake-ip 缓存 |
| Geo 数据库 | 触发更新 |
| 实时流 | 流量、内存、日志、连接，走 WebSocket |

安全边界是：controller 默认只监听 `127.0.0.1`；每次启动生成新的 secret，用 Bearer 认证；CORS 默认关闭，需要时才写 `external-controller-cors`。

「重载配置」这条路的存在，是绝大多数修改能热生效而不重启进程的前提。

## 内核策略

MVP 阶段只支持 App 自带的内置 Mihomo 核心。设置页会同时显示 App 版本、构建号和内置的 Mihomo 版本。

将来要支持自定义 core 通道，得先补齐 manifest、签名和哈希校验、helper 允许列表、UI 状态和回滚策略。在这些到位之前，让用户换 core 等于把一个未经校验的二进制交给特权 helper 去启动。

## 磁盘上的分工

| 位置 | 内容 |
| --- | --- |
| `Profiles/` | 你导入的原始 YAML，只读不改 |
| `Runtime/` | App 生成的运行时 YAML 与 provider 内容 |
| `Subscriptions/` | 订阅相关的中间产物 |
| `Logs/` | 运行时日志 |
| Keychain | 订阅 URL、端点密码 |

目录和文件权限见[文件与路径](/docs/reference/paths)。原始与运行时分离这条边界，是[运行时配置生成](/docs/advanced/runtime-config)的前提。
