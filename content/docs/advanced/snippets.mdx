title: 片段库

---

**路由** 页是 ClashMax 里唯一编辑运行时行为的地方。它的模型很小：一个**片段库**，每个片段是一段有类型的运行时补丁，按顺序合并进生成的配置。

## 四种片段类型

| 类型 | 改什么 | 典型用途 |
| --- | --- | --- |
| **规则** | `rules` | 加前置/后置规则、禁用配置自带的规则 |
| **DNS 补丁** | `dns` | 换解析器、改策略、fallback 过滤 |
| **嗅探** | `sniffer` | 控制嗅探哪些协议和端口 |
| **原始 YAML** | 任意键 | ClashMax 没有 UI 的一切 |

## 绑定范围

每个片段可以绑定到：

- **全部配置**：对所有配置生效。
- **指定配置**：只对勾选的配置生效（至少选一个）。

配置被删除后，绑定里失效的 ID 会被自动清掉。

## 顺序即优先级

片段库是**有序**的。同类型的片段按库中顺序折叠，后面的片段有更高优先级。拖动排序就是在改优先级。

### 规则的最终顺序

规则的合并结果是这样拼出来的：

```
前置规则（全局设置 → 配置级 → 片段）
配置自带规则（去掉被禁用匹配器命中的）
后置规则（配置级 → 全局设置 → 片段）
```

规则页对每一条规则都标了**规则来源**，直接告诉你它属于哪一层。

### 禁用规则

除了增加规则，规则片段还能**禁用**配置自带的规则，三种匹配方式：

| 方式 | 说明 |
| --- | --- |
| **包含** | 规则文本包含这段字符串 |
| **精确** | 完全相等 |
| **正则** | 正则匹配 |

被匹配到的规则从生成的配置里移除，**配置文件本身不动**。

### 可用的规则类型

新建规则时可以选：`DOMAIN`、`DOMAIN-SUFFIX`、`DOMAIN-KEYWORD`、`IP-CIDR`、`IP-CIDR6`、`GEOIP`、`GEOSITE`、`RULE-SET`、`SUB-RULE`、`SRC-GEOIP`、`SRC-IP-ASN`、`SRC-IP-CIDR`、`SRC-IP-SUFFIX`、`DST-PORT`、`SRC-PORT`、`IN-PORT`、`PROCESS-NAME`、`PROCESS-PATH`、`MATCH`。

其中 `IP-CIDR`、`IP-CIDR6`、`GEOIP` 支持 `no-resolve`。表单会当场显示这条规则的运行时形式，所见即所得。

## 原始 YAML 片段

这是 ClashMax 承诺的逃生舱：**任何 Mihomo 键都可以被用户片段覆盖，包括 App 没有 UI 的键。**

它在管线里排在所有 App 管理键**之后**，所以 `mode`、`tun.*`、`dns.enable`、geo 键、以及 `tcp-concurrent`、`ntp`、`keep-alive-interval`、`global-client-fingerprint` 这类 ClashMax 从没做过开关的键，全都能碰。

### 列表策略

| 策略 | 语义 |
| --- | --- |
| **替换列表** | 片段里的列表**就是**最终列表。`nameserver: [1.1.1.1]` 表示只有这一个解析器。唯一能让列表变短的策略。 |
| **追加到列表** | 片段的条目追加在生成条目之后。等同于遗留的 Runtime Merge YAML 语义。 |

### 保留键

有三类键原始片段**不能设置**：

```
mixed-port
external-controller / external-controller-tls / external-controller-unix / external-controller-pipe
secret
```

<Callout type="warn">
这不是天花板，而是保护逃生舱本身。`external-controller` 和 `secret` 是每一次应用、预检、回滚所依赖的通道；`mixed-port` 是 App 交给系统代理和 NE 代理的那个端口。片段一旦移动它们，App 就再也无法兑现「改错了能回滚」这个承诺。

这三个键在**设置**里改，改完系统代理、NE 代理和核心三方保持一致。
</Callout>

校验发生在两处：编辑器里即时校验，生成配置时**再校验一次**。后者不可省——一个片段也可能来自恢复的备份。

## 路由页的三个工具

### 生效配置

显示当前生成的完整运行时配置，以及**当前片段带来的差异**。敏感字段自动遮蔽。

这是回答「我的改动到底进没进去」的唯一权威视图——比读片段编辑器可靠，因为它显示的是核心真正会读到的东西。

### 诊断

集中呈现与路由有关的运行时事实：DNS 解析、fake-ip 状态与**清空 fake-ip 缓存**、geo 数据库状态与**立即更新**、嗅探诊断等。

它还会说清当前上下文，比如：

- 「TUN 已开启，其 DNS 劫持会把系统查询送到 Mihomo 的解析器。」
- 「NE 代理已开启，被捕获的查询会使用 Mihomo 的解析器。」
- 「没有流量捕获在生效，因此还没有查询到达 Mihomo 的解析器。」

最后一句是关键——DNS 配置得再对，没有流量进来也不会发生任何事。

### 匹配模拟器

给一组连接上下文，本地重跑一次规则匹配：

| 输入 | 说明 |
| --- | --- |
| 目标主机或 IP | 必填 |
| 源 IP | 可选 |
| 进程名或路径 | 可选 |
| 目标端口 / 源端口 / 入站端口 | 可选 |

输出是命中的规则和最终策略。**在应用改动之前**用它验证一条新规则会不会被前面某条更宽的规则抢先命中，比启动核心再抓包快得多。

从连接页点 **在「路由」页打开** 会把那条连接的上下文自动填进来。

## 保存时会发生什么

保存片段库时，ClashMax 会按[变更生效模型](/docs/advanced/apply-model)明确告诉你结果：热重载、需要重启、下次启动生效，或者被运行时拒绝后**回滚**。编辑器在你按下保存**之前**就会显示这条承诺。
