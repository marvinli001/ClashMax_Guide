## 三种来源

<Tabs items={['本地 YAML', '订阅', '手动代理']}>
<Tab value="本地 YAML">

**导入 YAML…** 选一个标准 Clash / Mihomo 配置。文件被复制进 ClashMax 的目录并**原样保存**，之后所有修改都发生在生成的运行时配置里，原文不动。

</Tab>
<Tab value="订阅">

**添加订阅…** 填 URL。ClashMax 会先抓一次内容并判断类型：

| 内容类型 | 处理方式 |
| --- | --- |
| 完整 Clash 配置 | 直接当配置用 |
| proxy-provider 内容 | 用生成模板包成一份可用配置 |
| 分享链接列表 | 同上 |
| Base64 分享链接列表 | 先解码，同上 |

订阅 URL 按配置 ID 存进 Keychain，不写在明文文件里。

</Tab>
<Tab value="手动代理">

**添加手动代理…** 用于你手上只有一个 SOCKS5 或 HTTP 端点的情况。ClashMax 会生成一份最小配置：一个出站节点，加上一组把 localhost 和私有网段放直连、其余走代理的规则。

同一处管理的**代理端点（Proxy Endpoints）**还能当**上游代理**用——让所有出站流量再经过一跳你自己的代理。

</Tab>
</Tabs>

## 生成模板

当订阅返回的不是完整配置时，ClashMax 需要自己组一份出来。**生成模板** 决定组成什么样：

| 模板 | 规则部分 |
| --- | --- |
| **Minimal** | 只有 `MATCH` 指向最终策略，最小可用 |
| **Global** | `MATCH` 全部指向生成的代理组 |
| **Rule** | 本地域名 + 私有 IPv4 网段直连，然后 `MATCH` |
| **CN Direct** | 私有网段和 CN geodata 直连，然后 `MATCH` |

v2 模板还会写入一份 App 管理的 DNS 基础块（fake-ip、系统 hosts、尊重规则的解析器默认值、fallback 过滤）。v1 是旧版模板，不带 DNS 基础块——如果你的配置是很早以前建的，DNS 覆盖面板不会把 DNS 记在模板头上。

生成的组名默认叫 `Proxy` 和 `Auto`，最终策略默认 `Proxy`，这三个都可以改。

## 订阅更新

### 更新间隔怎么定

自动更新的间隔按这个顺序解析，先命中者胜：

<Steps>
<Step>**关闭了自动更新** → 不更新。</Step>
<Step>**配置自己设了间隔覆盖** → 用它。</Step>
<Step>**允许跟随远端，且远端返回了 `profile-update-interval`** → 用远端的。</Step>
<Step>**都没有** → 用全局默认间隔。</Step>
</Steps>

无论哪一档，最终都会被夹到 30 分钟 ~ 7 天之间。配置详情里会直接告诉你当前用的是哪一档。

### 抓取时走哪条路

订阅本身也要联网，**下载方式（Fetch Proxy）** 决定它怎么走：

- **默认**：按内置顺序依次尝试
- **直连**：不经过任何代理
- **本地 Clash 代理**：经过 ClashMax 自己的混合端口（需要核心在跑）
- **系统代理**：经过 macOS 当前的系统代理

机场地址被墙时，「本地 Clash 代理」通常是唯一能成的一档——前提是你已经有一份能用的配置在跑。

### 更新前的预检

订阅抓回来之后，ClashMax 会先生成一份运行时配置，**交给 Mihomo 做一次预检**，通过了才替换现有配置。这样一份坏订阅不会把正在跑的核心带崩。预检输出在配置详情的 **Preflight Output** 里。

### 更新失败时

配置详情里有 **历史（History）**，记录每次更新的触发方式（导入 / 手动 / 自动 / 编辑来源）和结果，失败会分类：网络、HTTP 状态、解码、面板响应、配置非法、预检、取消、跳过。

订阅还会解析 `subscription-userinfo` 头，显示已用流量和到期时间，并在这些情况提前告警：额度已用尽、剩余低于 10%、7 天内到期、已过期。

## Provider 选项

订阅类配置有一组 **provider 选项**，控制生成出来的配置长什么样：

| 选项 | 作用 |
| --- | --- |
| `filter` / `excludeFilter` / `excludeType` | 按名称或类型筛节点 |
| 主组名 / Auto 组名 / 最终策略 | 生成配置的组织方式 |
| 配置级规则覆盖 | 只对这一份配置生效的规则增删 |
| 请求头 | 抓订阅时额外带的 HTTP 头（开发者模式） |

改这些选项时，ClashMax 会给出一份 **运行时差异（runtime diff）**：改动前后生成模板的对比，加上风险标记（信息 / 警告 / 危险）。如果改完之后核心起不来，配置详情里有 **回滚到上次可用（Rollback to Last Working）**。

<Callout>
`Runtime Merge YAML` 和 `Provider Override YAML` 是遗留字段（需要开发者模式）。它们在 ClashMax 写入自己管理的键**之前**合并，所以覆盖不了 `mode`、`tun.*`、`dns.enable` 这些键——那从来就不是一个真正的逃生舱。现在想覆盖任意 Mihomo 键，用[路由页的原始 YAML 片段](/docs/advanced/snippets)。
</Callout>

## 从其他客户端迁移

**从其他客户端导入…** 支持 ClashX、FlClash、Clash Verge。ClashMax 会扫描它们的数据目录，给出一份迁移报告：来源、可导入的配置、订阅、规则片段、运行时设置、冲突、警告、已检查的文件。你可以分别选择导入本地配置、规则片段、全局快捷键。

不受支持的映射会明确列出来，而不是悄悄丢掉。
