## 备份包含什么

**设置 → 备份与恢复 → 导出** 生成一个备份文件，里面有：

- 配置清单与配置文件内容
- 代理端点清单
- App 设置快照
- 各代理组的节点选择
- 路由页的运行时片段库

## 机密数据是可选的

导出时有一个 **包含加密机密（Include encrypted secrets）** 开关：

<Tabs items={['不包含机密', '包含机密']}>
<Tab value="不包含机密">

订阅 URL、代理端点密码等不写进备份。备份里会带一份**被省略机密的摘要**，说明哪些东西没被导出——恢复后你得手动补回去。

适合：分享配置结构给别人、放进不受信任的存储。

</Tab>
<Tab value="包含机密">

需要设置**备份密码**（并确认一次）。机密、配置源和运行时片段会被加密后写入。

适合：换机、自己留档。

<Callout type="warn">
密码丢了就恢复不出机密部分。ClashMax 不保存这个密码，也没有找回途径。
</Callout>

</Tab>
</Tabs>

## 恢复

**设置 → 备份与恢复 → 恢复**，选文件、按需填密码。密码留空表示只恢复非机密部分。

<Callout type="warn">
**恢复前必须先停止核心。** 核心在运行时恢复按钮是禁用的——恢复会替换配置清单和运行时片段库，在运行中做这件事会让磁盘状态和内存状态对不上。
</Callout>

恢复完成后会告诉你恢复了几个配置、跳过了几个机密。

## 从其他客户端迁移

在 **配置 → 从其他客户端导入…**，支持 ClashX、FlClash、Clash Verge。

流程是先扫描再确认：ClashMax 读取对方的数据目录，生成一份迁移报告，你看完再决定导入什么。报告分这几块：

| 分块 | 内容 |
| --- | --- |
| 来源 | 扫到的客户端与路径 |
| 配置 / 订阅 | 可导入的条目 |
| 规则片段 | 可导入的规则集合 |
| 运行时 | 可迁移的运行时设置 |
| 冲突 | 与现有数据重名或矛盾的地方 |
| 警告 | 能导入但要注意的地方 |
| 已检查的文件 | 扫描过的完整文件列表 |

可以分别勾选是否导入本地配置、规则片段、全局快捷键。

<Callout>
不受支持的映射会被**明确列出来**，而不是悄悄丢弃。迁移完扫一眼这一节，就知道有哪些东西需要手工重建。
</Callout>

## 建议的备份节奏

- **改动前**：动 provider 选项或写复杂片段之前，先导一份不含机密的备份。出问题可以对照差异。
- **换机时**：导一份含机密的加密备份，密码存在密码管理器里。
- **日常**：不需要定期备份——配置本身来自订阅，重新拉一次就有了；真正难重建的是片段库和代理组选择，而这两样在任何一份备份里都有。
