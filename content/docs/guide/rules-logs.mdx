## 规则页

**规则** 页是**只读**的：它显示核心当前实际加载的规则，按顺序编号。想改规则去[路由页](/docs/advanced/snippets)。

每条规则显示类型、载荷、目标策略。来自 rule-provider 的规则会标出 provider 名。选中一条还能看到：

- **规则来源**：这条规则是从哪一层来的（配置自带、全局覆盖前置、片段前置、片段后置……）
- **在规则 #N 之前评估**：它在整条链上的位置

这两条信息合起来回答一个高频问题：「我加的规则为什么没生效」——多半是被前面某条更宽的规则先命中了。

### 筛选

右键菜单能一键收窄视图：

- 只看某一类型的规则
- 只看路由到某个策略的规则
- 只看某个 rule-provider 的规则

顶部搜索框有自己的语法，点 **搜索语法** 能看到说明。

### Rule Provider

**规则 Provider** 面板可以全部更新或单独更新。

<Callout>
Provider 更新需要核心在运行——它是通过 Mihomo 控制面下发的，核心没起来就没有可下发的对象。
</Callout>

### 快捷动作

**在此规则前插入…** 会带着位置上下文跳到路由页，让你新写的规则正好排在这条前面。这比自己数序号可靠。

## 日志

**日志** 页是核心运行时日志的实时流，可以按级别筛选、复制单行或整段消息。

### 日志级别的正确用法

**设置 → 运行时 → 日志级别** 有 Info / Warning / Error / Debug 四档。这个设置改的是核心本身的输出级别，同时也决定日志页显示什么。

<Callout type="warn">
早期版本有个坑：选了 Debug，核心确实按 debug 输出了，但页面又把 debug 条目过滤掉了，结果看起来「Debug 级完全没有输出」。现在**日志级别是唯一权威**——选了 Debug 就能看到 debug 条目。开发者模式只会让**安静的**级别多显示一些内容，不会反过来遮挡你主动要求的详细输出。
</Callout>

平时留在 Info。排查具体故障时临时切到 Debug，问题解决后切回去——debug 级日志量很大。

### 日志文件

**状态 → 更多** 里有 **打开日志** 和 **打开日志文件夹**，可以直接拿到磁盘上的日志（路径见[文件与路径](/docs/reference/paths)）。

<Callout type="warn">
提交 Issue 前先把日志里的订阅 URL、节点凭据和私有域名删掉。或者用状态页的 **复制诊断**，它输出的是一份**已脱敏**的报告。
</Callout>
