首页告诉你有没有问题，状态页告诉你具体是什么情况。它是只读的诊断视图，除了明确的修复按钮之外不做任何修改。

## 概览

页面最上方是四行基本事实：模式（当前代理路由）、配置（当前配置名）、核心（核心状态）、运行模式（规则 / 全局 / 直连）。

## 需要处理

这一节只在真的有问题时出现。每个条目自带对应的修复动作：修复 Helper、打开系统设置、修复 DNS、修复路由、关闭残留的系统代理，或者展开对应的详情分组。

## 详情分组

| 分组 | 内容 |
| --- | --- |
| 运行时 | 端口、控制器端点、生效的运行时覆盖 |
| DNS | DNS 是否启用、生效的解析器、fake-ip 状态 |
| 规则覆盖 | 当前生效的前置、后置、禁用规则 |
| Helper | TUN helper 的注册与协议版本状态 |
| TUN 诊断 | 仅 TUN 模式显示 |
| NE 诊断 | 仅 NE 代理模式显示 |

默认展开哪几个分组按当前情况决定。TUN 模式下 helper 有问题就默认展开 helper 和 TUN，一切正常就只展开运行时。

## 复制诊断

「复制诊断」生成一份已脱敏的报告，提交 Issue 时附这个。它比截图信息量大，又不会像原始日志那样把订阅 URL 泄出去。

<Callout type="warn">
粘贴前还是扫一眼。私有域名可能出现在你自己写的规则里，脱敏规则不知道那些是敏感的。
</Callout>

## 其他入口

「更多」菜单里有打开日志、打开日志文件夹、修复 Helper、打开 Helper 批准设置。TUN 模式下还有刷新 TUN 诊断。

## 提问时给什么

1. 状态页的「复制诊断」输出。
2. 你期望发生什么，实际发生了什么。
3. 连接页里那条有问题的连接：目标、域名可见性、命中的规则、链路。
4. 核心报错的话，日志里对应时间点的几行，脱敏后。

反馈渠道见[常见问题](/docs/reference/faq)。
