title: 状态与诊断

---

首页告诉你「有没有问题」，**状态** 页告诉你「具体是什么情况」。它是只读的诊断视图，不做任何修改（除了明确的修复按钮）。

## 概览

页面最上方是四行基本事实：

- **模式**：当前代理路由（系统代理 / TUN / NE 代理）
- **配置**：当前配置名
- **核心**：核心状态
- **运行模式**：规则 / 全局 / 直连

## 需要处理

这一节**只在真的有问题时出现**。一切正常时它不显示——概览行已经说了运行时是健康的，再放一个「全部正常」的框只是重复。

每个问题条目都自带对应的修复动作：修复 Helper、打开系统设置、修复 DNS、修复路由、关闭残留的系统代理，或者展开对应的详情分组。

## 详情分组

| 分组 | 内容 |
| --- | --- |
| **运行时** | 端口、控制器端点、生效的运行时覆盖 |
| **DNS** | DNS 是否启用、生效的解析器、fake-ip 状态 |
| **规则覆盖** | 当前生效的前置 / 后置 / 禁用规则 |
| **Helper** | TUN helper 的注册与协议版本状态 |
| **TUN 诊断** | 仅 TUN 模式显示 |
| **NE 诊断** | 仅 NE 代理模式显示 |

默认展开哪几个分组是**按当前情况决定**的：TUN 模式下 helper 有问题，就默认展开 helper 和 TUN；一切正常就只展开运行时。

## 复制诊断

**复制诊断** 会生成一份**已脱敏**的报告。它是提交 Issue 时该附的东西——比截图信息量大，又不会像原始日志那样把订阅 URL 泄出去。

<Callout type="warn">
即便如此，粘贴前也扫一眼。私有域名可能出现在你自己写的规则里，脱敏规则不知道那些是敏感的。
</Callout>

## 其他入口

**更多** 菜单里还有：

- **打开日志** / **打开日志文件夹**
- **修复 Helper** / **打开 Helper 批准设置**
- TUN 模式下：**刷新 TUN 诊断**

## 提问的正确姿势

按这个顺序给信息，问题通常一轮就能定位：

<Steps>
<Step>状态页的**复制诊断**输出。</Step>
<Step>你**期望**发生什么，**实际**发生了什么。</Step>
<Step>连接页里那条有问题的连接：目标、域名可见性、命中的规则、链路。</Step>
<Step>如果核心报错，日志里对应时间点的几行（脱敏后）。</Step>
</Steps>

反馈渠道见 [常见问题](/docs/reference/faq)。
