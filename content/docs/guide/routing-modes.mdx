---

**代理路由**决定 macOS 的流量以什么方式进入 ClashMax。它和 **运行模式**（规则 / 全局 / 直连）是两回事：路由模式管「流量怎么进来」，运行模式管「进来之后怎么分流」。

路由模式在**启动时**读取，所以要先选好再启动核心。

## 三者对比

| | 系统代理 | TUN | NE 代理 |
| --- | --- | --- | --- |
| 原理 | 改 macOS 代理设置 | 虚拟网卡接管路由 | Network Extension 透明代理 |
| 需要授权 | 否 | 特权 helper | 系统扩展 |
| 覆盖范围 | 遵守系统代理的 App | 几乎全部流量 | 透明代理捕获的流量 |
| UDP | 不接管 | 接管 | 接管 |
| 成熟度 | 稳定，默认 | 稳定 | **实验性** |

## 系统代理

默认，也是最省事的一档：核心以普通用户态进程运行，ClashMax 把 macOS 的 HTTP / HTTPS / SOCKS 代理指向自己的混合端口，停止时恢复原状。

不需要任何授权，代价是**只有遵守系统代理设置的 App 才会被代理**。命令行工具、走原生 socket 的客户端、以及所有 UDP 流量都不受影响。

### 绕过列表与代理守卫

首页的**系统代理设置**里可以调：

- **代理主机**：默认 `127.0.0.1`。填 `0.0.0.0` 之类的通配地址会被规范回默认值。
- **使用默认绕过**：内置一组常见条目（`localhost`、`127.0.0.1`、`::1`、`*.local`、`<local>`、`169.254/16`、以及 10/8、172.16/12、192.168/16 私有网段）。
- **自定义绕过**：追加你自己的条目，支持域名、通配符和 CIDR。
- **校验绕过条目**：打开后会拒绝明显写错的条目，而不是让它静默失效。
- **代理守卫**：按设定间隔（5~600 秒）检查系统代理设置有没有被别的软件改掉，被改了就重新写回去。

<Callout>
被别的代理软件抢走系统代理设置是最常见的「明明在跑却不走代理」原因。装了多个客户端就打开代理守卫。
</Callout>

## TUN

由特权 helper 建立虚拟网卡，VPN 式接管路由，能覆盖不理会系统代理的程序和 UDP。

### 授权流程

第一次切到 TUN 并启动时，macOS 会要求批准 helper。**设置 → 系统 → TUN Helper 状态** 会显示当前处于哪一步：

| 状态 | 含义与动作 |
| --- | --- |
| 尚未检查 | 点一次刷新 |
| 未注册 | 点「注册」，或直接在 TUN 模式下启动 |
| 等待批准 | 去 **系统设置 → 通用 → 登录项与扩展** 打开 ClashMax；ClashMax 会自己发现 |
| 已注册并完成启动准备 | 正常 |
| 协议版本过旧 / launchd 起不来 | 点 **修复 Helper** 重装内置 helper，需要时再批准一次 |

<Callout type="warn">
LaunchDaemon 的批准由 macOS 掌管。点「注册」有可能直接打开系统设置，而不是弹出 App 内的权限表单——这是正常的。
</Callout>

### TUN 设置

首页的 **TUN 设置** 里能调协议栈（System / GVisor / Mixed）、设备名、`auto-route`、`strict-route`、`auto-detect-interface`、DNS 劫持、MTU，以及**排除路由网段**——你写的排除项会和配置里已有的 `route-exclude-address` 合并去重。

同一个面板里还有 Fake IP 开关、Fake IP 范围与过滤器，以及一整套 DNS 覆盖。DNS 部分的设计见 [DNS 与嗅探](/docs/advanced/dns-sniffer)。

<Callout>
macOS 的 TUN 运行时配置**不会**写入 `auto-redirect`——那是 Linux 专有的键。
</Callout>

## NE 代理（实验性）

走 Network Extension 的透明代理路径，不碰特权 helper。**设置 → NE 代理** 下能看到系统扩展状态、透明代理状态和 NE 诊断。

它有两条实实在在的限制：

- **入站端口和控制器端点在隧道启动时就被固定了。** 之后改混合端口或控制器端口，必须重启运行时才生效，App 会明确告诉你这一点。
- **NE 路由设置（DNS 捕获、fake-ip、系统 DNS 覆盖）只在隧道启动时读取。** 改了同样要重启。

其他改动（规则、DNS 补丁、嗅探、原始 YAML）仍然是热重载。这个边界的完整规则见[变更生效模型](/docs/advanced/apply-model)。

## 出问题时先看首页

首页会主动报出下面这些情况，每条都带修复入口：

- **核心在跑，但没有捕获到流量** —— 路由没接上。系统代理模式下多半是系统代理开关没打开。
- **系统代理仍指向旧端口** —— macOS 里存着一个 ClashMax 的旧端口，点修复。
- **TUN helper 需要处理** —— 授权掉了或 helper 版本过旧。
- **TUN / NE 系统 DNS 需要修复** —— 系统 DNS 被改动后没有还原干净。

想看更细的事实（而不只是「有问题」），去[状态页](/docs/guide/status)。
