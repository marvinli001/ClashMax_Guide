---
title: 第一次跑起来
description: 导入配置、启动核心、确认流量真的走了代理。
---

目标是五分钟内看到一条真实连接。

<Steps>
<Step>
### 准备一份配置

ClashMax 接受三类来源，都在 **配置（Profiles）** 页：

| 来源 | 入口 | 说明 |
| --- | --- | --- |
| 本地 YAML | 导入 YAML… | 标准 Clash / Mihomo 配置文件 |
| 订阅 | 添加订阅… | 机场链接，可返回完整配置或节点列表 |
| 手动代理 | 添加手动代理… | 手上只有一个 SOCKS5 / HTTP 端点时用 |

订阅返回的内容 ClashMax 会自动识别是完整配置、proxy-provider 内容、分享链接列表还是 Base64 列表；后三种它会用一份生成模板包出一个可用配置。详见[配置与订阅](/docs/guide/profiles)。
</Step>

<Step>
### 设为当前配置

在配置列表里选中它，**设为当前（Set as Current）**。只有当前配置会被拿去生成运行时配置。
</Step>

<Step>
### 选路由模式

**设置 → 系统 → 代理路由**，三选一：

- **系统代理**：默认，推荐先用这个。改 macOS 的 HTTP/HTTPS/SOCKS 代理设置，不需要任何授权。
- **TUN**：VPN 式接管，需要批准特权 helper。
- **NE 代理**：实验性的 Network Extension 透明代理，需要批准系统扩展。

选择在**启动时**生效，所以先选好再启动。三者的取舍见[路由模式怎么选](/docs/guide/routing-modes)。
</Step>

<Step>
### 启动核心

回到 **首页**，点 **启动核心**。状态会从 `启动中` 走到 `运行中`。

用系统代理模式时，启动核心与开启系统代理是两件事——首页上有独立的系统代理开关，只有它打开了，macOS 才会把流量交给 ClashMax。
</Step>

<Step>
### 确认流量真的走代理

首页不只显示「运行中」，它还会自己检查**是否真的在代理**，并在下面几种情况给出具体提示：

- 「核心在跑，但没有捕获到流量」——核心起来了，可路由没接上。
- 「系统代理仍指向旧端口」——macOS 里存着一个 ClashMax 的旧端口。
- 「TUN helper 需要处理」/「NE 系统 DNS 需要修复」——对应模式的授权或 DNS 状态不对。

每条提示旁边都有修复按钮。看到公网 IP 卡片变成节点出口地址，就说明真的通了。
</Step>
</Steps>

## 跑通之后先做三件事

1. **测一次延迟。** 去 **代理** 页，对当前组点 **测试延迟**，心里有个节点质量的底。
2. **看一眼连接。** 打开 **连接** 页，随便刷个网页，确认目标域名、命中的规则、走的链路都符合预期。
3. **打开菜单栏。** 日常切节点、切模式不需要开主窗口，菜单栏面板就够了。

<Callout>
如果你打算长期用，把 **设置 → 启动** 里的 **登录时启动** 和 **静默启动** 打开，开机后 ClashMax 只出现在菜单栏。
</Callout>
