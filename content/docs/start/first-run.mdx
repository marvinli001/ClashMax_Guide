---
title: 第一次跑起来
description: 导入配置、启动核心、确认流量真的走了代理。
---

<Steps>
<Step>
### 准备一份配置

配置页有三个入口：

| 来源 | 入口 | 说明 |
| --- | --- | --- |
| 本地 YAML | 导入 YAML… | 标准 Clash / Mihomo 配置文件 |
| 订阅 | 添加订阅… | 机场链接，可以返回完整配置或节点列表 |
| 手动代理 | 添加手动代理… | 手上只有一个 SOCKS5 / HTTP 端点时用 |

订阅返回的内容 ClashMax 会自动识别：完整配置、proxy-provider 内容、分享链接列表或 Base64 列表。后三种它会套一份生成模板包成可用配置，细节见[配置与订阅](/docs/guide/profiles)。
</Step>

<Step>
### 设为当前配置

在列表里选中它，点「设为当前」。只有当前配置会被拿去生成运行时配置。
</Step>

<Step>
### 选路由模式

**设置 → 系统 → 代理路由**，三选一：

- 系统代理：默认，先用这个。改 macOS 的 HTTP/HTTPS/SOCKS 代理设置，不需要授权。
- TUN：VPN 式接管，要批准特权 helper。
- NE 代理：实验性的 Network Extension 透明代理，要批准系统扩展。

这个选择在启动时读取，所以先选好再启动。取舍见[路由模式怎么选](/docs/guide/routing-modes)。
</Step>

<Step>
### 启动核心

回到首页点「启动核心」，状态会从「启动中」走到「运行中」。

系统代理模式下，启动核心和开启系统代理是两件事。首页上有独立的系统代理开关，打开它 macOS 才会把流量交给 ClashMax。
</Step>

<Step>
### 确认流量真的走代理

首页除了显示「运行中」，还会自己检查是不是真的在代理，遇到下面几种情况会给出提示：

- 核心在跑，但没有捕获到流量。核心起来了，路由没接上。
- 系统代理仍指向旧端口。macOS 里存着一个 ClashMax 的旧端口。
- TUN helper 需要处理，或者 NE 系统 DNS 需要修复。

每条提示旁边都有修复按钮。公网 IP 卡片变成节点出口地址就说明通了。
</Step>
</Steps>

## 跑通之后

去代理页对当前组测一次延迟，心里有个节点质量的底。打开连接页随便刷个网页，确认目标域名、命中的规则、走的链路都符合预期。日常切节点和切模式用菜单栏就够，不用开主窗口。

打算长期用的话，把 **设置 → 启动** 里的「登录时启动」和「静默启动」打开，开机后 ClashMax 只出现在菜单栏。
