主窗口左侧是固定的九个页面。它们的分工是有意划开的：**看状态**、**改配置**、**查问题**三类互不混杂。

| 页面 | 一句话职责 | 什么时候来 |
| --- | --- | --- |
| **首页** | 运行控制 + 是否真的在代理 | 启停核心、切运行模式、发现异常 |
| **状态** | 只读诊断详情 | 首页提示有问题，来这里看具体事实 |
| **配置** | 配置文件与订阅管理 | 导入、更新订阅、改 provider 选项 |
| **代理** | 代理组与节点 | 换节点、测延迟、跑 provider 健康检查 |
| **连接** | 实时连接列表 | 「这个 App 到底走了哪条链路」 |
| **路由** | 运行时片段库 | 加规则、打 DNS 补丁、写原始 YAML |
| **规则** | 当前生效的规则列表 | 确认某条规则在不在、排第几 |
| **日志** | 运行时日志流 | 核心报错、连接失败的一手信息 |
| **设置** | App 与运行时选项 | 端口、路由模式、备份、更新 |

## 三个容易混淆的边界

### 首页 vs 状态

**首页**回答「现在正常吗、要不要我做点什么」，只在出问题时显示条目；**状态**回答「具体是什么情况」，把运行时、DNS、规则覆盖、helper、TUN/NE 诊断分组摊开，还能一键复制一份**已脱敏**的诊断报告。

### 规则 vs 路由

**规则**页是只读的——它显示核心当前实际加载的规则，包括来自 rule-provider 的。**路由**页才是编辑的地方，你在那里写的东西会被合成进运行时配置，然后才出现在规则页。

想从一条具体连接反查规则，在连接页选中它，点 **为何命中此规则**；要新增一条针对它的规则，点 **在「路由」页打开**。

### 代理 vs 连接

**代理**页是「我可以选什么」，**连接**页是「实际发生了什么」。节点选对了但连接页显示走了 DIRECT，问题在规则不在节点。

## 菜单栏

菜单栏面板是主窗口的轻量版：运行状态、流量图、运行模式、常用代理组切换、检查更新。日常使用大多数时候不需要打开主窗口。菜单栏图标旁默认还会显示实时上下行速度，可以在 **设置 → 通用 → 菜单栏流量速度** 关掉。

详见[菜单栏与快捷键](/docs/guide/menubar)。

## 开发者模式

**设置 → 通用 → 开发者模式** 打开后会多出一些东西：全局快捷键设置、helper 诊断与日志、外部控制器（External Control）选项、订阅的旧版 raw provider 过滤器与自定义请求头。

<Callout>
开发者模式不是「覆盖 Mihomo 键」的前提。想改任意 Mihomo 键，用[路由页的原始 YAML 片段](/docs/advanced/snippets)，它有完整的预检和回滚。
</Callout>
